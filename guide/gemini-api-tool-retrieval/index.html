Gemini API Tool Retrievalとは？使い方と仕事・副業で試す手順

先に結論

Tool Retrievalとは、GeminiのAPIで、AIエージェントが持つたくさんのツールのうち、その場の作業に必要なものだけを読み込ませる新機能です。2026年11月19日にGoogleが発表し、Interactions APIのプレビューとして提供されています。使い方は、リクエストに `tool_search` を足し、普段あまり使わないツールに `defer_loading: true` を付ける形で、検索用の仕組みを自分で作って置く必要はないと説明されています。

  • Gemini APIの機能です。チャットの画面で押すボタンではなく、APIでエージェントを作る人向けの発表です。
  • ツールが増えるほど、毎回モデルに渡す情報を減らせる設計です。
  • Tool Retrieval自体に別料金はなく、トークンは使うモデルの標準料金で数えられます。
  • 対応モデルはGemini 3.6以降です。
  • 提供する地域や、ツール数の上限は、発表には書かれていません。

Tool Retrievalとは？何が発表されたか

発表元はGoogleの公式ブログで、日付は2026年11月19日です。題は、Gemini APIにTool Retrievalが入ったことを知らせる英語の記事で、出典は次のページです。

https://blog.google/innovation-and-ai/technology/developers-tools/gemini-api-tool-retrieval/

発表の中身を、自分の言葉でまとめます。AIエージェントに「予定を入れる」「メールを下書きする」「表に転記する」のような仕事をさせるとき、それぞれの仕事を、ツール（関数）としてモデルに教えておきます。ツールが増えると、その説明を毎回まるごと送ることになり、トークンの消費と待ち時間が増えます。Tool Retrievalは、ここを変える機能です。

仕組みは、サーバー側で検索する形です。遅延させたいツールは、名前と説明だけがモデルに見えて、細かい入力の形（パラメータスキーマ）は最初は読み込まれません。モデルが使いたいツールを名前で選ぶと、APIがその時点で中身を読み込み、同じリクエストの中で呼び出しまで進みます。検索用のインデックスを自分で作ってホストする必要はない、と書かれています。

何が変わるか？

変わるのは、ツールをたくさん持たせたときの重さの扱いです。これまでは、増やせば増やすほど毎回の入力が膨らむので、ツールを絞って持たせる工夫が要りました。Tool Retrievalを使うと、普段使わないツールは名前と説明だけを持たせておき、必要になったときだけ中身を呼ぶ形にできます。

もう一つ、デバッグがしやすくなります。検索の流れは `interaction.steps` に `tool_search_call`、`tool_search_result`、`function_call` として残るので、モデルがどのツールを探して、何を呼んだかを後から見られます。

自分の側で検索したい場合の道も用意されています。独自のツール置き場や、人ごとの権限による絞り込みを使いたいときは、`tool_search` に `"execution": "client"` を指定します。この場合は検索がアプリ側で動くため、検索のたびにやり取りが一往復増えます。ツールを前もって宣言せず、会話の途中で新しく出すこともできます。

仕事や副業でどう使うか？

この機能が効くのは、ツールが多い自作のエージェントです。たとえば、小さな事業を一人で回している人が、予定の登録、問い合わせメールの下書き、スプレッドシートへの転記、請求書の文面づくり、SNS投稿の下準備を、一つの自分専用エージェントにまとめたい場面です。ツールが数個なら使わなくても困りませんが、増やしていく途中で重さが気になってきたら試す価値があります。

プログラムは、コードを書ける人が自分で書くほか、Claude Code初心者の使い方で書いたように、ツールに日本語で指示して作る人もいます。そのうえでGemini APIを使うなら、次の手順で試せます。ここに書くのは公式の利用手順をもとにした進め方で、動くかどうかはご自身の環境で確かめてください。

  1. 手元のツールを書き出します。名前と、何をするかの一行説明を並べ、毎日の依頼で使う物と、たまにしか使わない物に分けます。
  2. リクエストに `tool_search` を足し、たまにしか使わないツールに `defer_loading: true` を付けます。よく使うツールは遅延させません。
  3. 実際の仕事の依頼を一つ出し、`interaction.steps` を開いて、モデルが選んだツールが思った物か確かめます。
  4. 遅延させる前と後で、入力トークンの使用量を自分の画面で見比べます。節約が出やすいのは、使われないツールが多い大きな構成だと公式は書いています。自分の構成で効くかは、測るまで分かりません。

分かれ道を図にすると、次のとおりです。

使う前に確かめること

公式の発表に書かれていることと、書かれていないことを分けて並べます。

  • 提供状況：Interactions APIのプレビューです。プレビューなので、仕様が変わる可能性は頭に置いてください。
  • 対応モデル：Gemini 3.6以降で、Gemini 4のモデルも含まれると書かれています。
  • 料金：Tool Retrieval自体に別料金はありません。入力と出力のトークンは、使うモデルの標準料金です。`tool_search` を有効にすると少量の固定の入力が加わり、読み込まれたスキーマは、その会話の残りの間、入力として数えられます。
  • 提供する地域：発表には書かれていません。
  • ツール数の上限やレートの制限：発表には書かれていません。
  • 固定で加わる入力の量：具体的な数字は発表には書かれていません。

読み込まれたスキーマが会話の残りの間ずっと数えられる点は、見落としやすいところです。多くのツールが毎回読み込まれる使い方だと、期待したほど減らない場合があります。

また、モデルが名前と説明を見てツールを選ぶ仕組みなので、名前や説明があいまいだと、思った物が選ばれにくくなると考えられます。これは発表に書かれた事ではなく、仕組みから考えた注意点です。一行説明は、何をする物かが分かる具体的な言葉で書いておくと安全です。

よくある質問

Q. Tool Retrievalとは、一言でいうと何ですか。

AIエージェントが持つ多数のツールのうち、必要になった物だけの詳しい情報をあとから読み込む、Gemini APIの機能です。毎回すべてのツールの説明を送らずに済むので、ツールが多い構成で入力を減らせる設計になっています。

Q. プログラミングをしない人にも関係がありますか。

この発表はAPIの機能なので、直接使うのは、APIでエージェントを作る人です。普段チャットのAIを使っているだけの方は、すぐに触る場面はありません。ただ、AI自動化や自分専用の秘書を作る段階に進むと関係してくるため、考え方だけ知っておくと役立ちます。

Q. 使うと料金は上がりますか、下がりますか。

発表では、Tool Retrieval自体の別料金はなく、トークンは使うモデルの標準料金だと書かれています。減るか増えるかは、使われないツールがどれだけあるかで変わると説明されており、具体的な金額や割合は発表には書かれていません。自分の使用量で見比べて確かめてください。

Q. 日本からでも使えますか。

提供する地域は、発表には書かれていません。試す前に、公式のドキュメントと、ご自身のアカウントでの表示を確認してください。

Q. ツールを自分で検索する方式は、どんなときに選びますか。

独自のツール置き場や、人ごとの権限で絞り込みたいときです。`execution: "client"` を指定すると、検索をアプリ側で動かせます。検索のたびにやり取りが一往復増える点は、公式が注意として書いています。
